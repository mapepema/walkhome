# Collectible cards: themes, generation, validation

Schema: `docs/CONTRACT.md` section 3 (`CardCatalog`). A theme = `content/cards/<theme>.json` + images in `frontend/public/cards/<deck>/<set>/`. A deck is published under the id of the journey it rewards (the default `camino` journey draws from the "Embers & Peaks" deck).

## Catalogs

| theme (deck) | cards | sets | source | licence |
|---|---|---|---|---|
| `camino` (Embers & Peaks) | 120 | `em` Embers (60), `pk` Peaks (60) | generated by code (`tools/build_cards.mjs`, texts in `tools/data/embers_peaks_cards.mjs`) | original, same licence as the project |

## Regenerating

```bash
# Embers & Peaks (about 20 s; --force rewrites everything)
node tools/build_cards.mjs [--force] [--only <slug>]
# check (standard library only; non-zero exit code on error)
python3 -I tools/validate_cards.py [camino]
```
The scripts use `sharp` and `@napi-rs/canvas` from `frontend/node_modules` (run `npm ci` in `frontend/` first) and the
Cinzel and Inter fonts from `frontend/public/fonts/` (override with `CINZEL_TTF=…` / `INTER_TTF=…`). The output is
**deterministic** (FNV-1a hashes, no randomness).

## Rarity

Embers & Peaks: quotas 62/31/16/7/3/1 (common/uncommon/rare/holo/ultra/secret). A few "legendary" cards have a fixed
rarity (`LEGENDARY` in `tools/data/embers_peaks_cards.mjs`); the rest is distributed by hash rank.
`foil`: none (common/uncommon), linear (rare), cosmos|reverse (holo), rainbow|cosmos (ultra), rainbow (secret).
The draw depends on the pack *odds*, not on these proportions.

## Adding a theme or a set

1. Create the journey pack `content/<theme>.json` (see `tools/build_content.py`: stages, biomes and events in km).
2. Copy `tools/build_cards.mjs` (set `THEME` and `DECK`): for each card produce `<slug>.webp` (≈ 480×672, ≤ 60 KB) and
   `<slug>.thumb.webp` (≈ 240×336, ≤ 18 KB), one `pack.webp` per set (`makePack()` from `tools/lib/common.mjs`,
   360×640 with alpha), and write `content/cards/<theme>.json` (id `<theme>:<set>:<slug>`, normalised `art_rect` =
   area where foil is allowed, `pack: PACK`).
3. `python3 -I tools/validate_cards.py <theme>`; add the deck folder to the validator's `DECKS` and a size budget in `PACK_MB`.
4. A new set for an existing theme: add the entry to `SETS` and the cards to `tools/data/embers_peaks_cards.mjs`
   (or the theme's own source), then rerun the script.

## Size on disk (Raspberry Pi)

Embers & Peaks ≈ **3.4 MB**. The frontend loads `thumb` in grids and `image` only in the detail view and the pack opening.
WebP quality is adaptive (q78, then lowered in steps of 4 while above 60 KB / 18 KB).
